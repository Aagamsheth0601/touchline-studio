# Ask about this decision

After a replay finishes, the visitor can ask one question about the selected move. Changing moves or scenarios removes the form and aborts its pending browser request. The old coaching-library search remains available independently.

## Request flow

1. The browser sends only question, scenario ID and choice ID to `decision-answer`.
2. The server validates the IDs against its checked-in scenario snapshot. Tests compare that snapshot with the game; update both when changing a scenario.
3. An atomic database budget allows at most five requests per minute and 100 per UTC day across the demo. It stores counters, not questions or visitor identifiers.
4. The question gets a gte-small embedding. The existing cosine-search RPC returns up to three notes; the answer service keeps matches at or above 0.82 belonging to this scenario or both scenarios.
5. No matching notes returns a fixed insufficient-evidence response. Obvious credential requests are also refused before provider use.
6. Gemini 2.5 Flash-Lite receives the trusted scenario and retrieved notes, with the question treated as untrusted data. It returns structured JSON with note IDs.
7. The service rejects interrupted output, unknown citations, malformed output and an altered opening replay fact. Source URLs are taken from retrieved database rows, never generated by Gemini.

Citation membership and the opening fact are enforceable checks; they do not prove that every later sentence is supported. These are experimental learning explanations, not expert-reviewed coaching or predictions. The small test set is not an accuracy benchmark. Short questions may be refused when retrieval lacks relevant evidence; filtering after top-three retrieval can omit another relevant note.

## Configuration and cost constraint

- User confirmed the Gemini project is **Free tier**, with a screenshot, before live calls. Billing was not enabled. There is one fixed model and no paid provider/model fallback.
- `GEMINI_API_KEY` is stored only in Supabase secrets, entered by the user. Never put it in a Vite variable, browser bundle, Git or chat.
- `DECISION_ANSWERS_ENABLED=true` enables the endpoint; setting it to false is the kill switch.
- Apply migration 005 and deploy the function with legacy JWT verification enabled. Browser requests use the existing public anon gateway key. The dashboard deployment inlines the local contract and scenario JSON into index.ts; the repository retains the separate source files for testing.
- Free tier is an account billing property, not a per-request switch. Keep the Google project unbilled. If its tier changes later, disable this feature and review before further use. Quota exhaustion displays an error; there are no automatic retries or upgrades.
- This feature does not persist questions. Requests reach Supabase and Google; their platform logging/data policies still apply. Do not submit personal information.

## Verification

27 unit tests and production build passed. Real requests exercised both pass choices and both two-on-one choices; the source membership and opening facts were checked, and responses were read for obvious role/context errors. Bread-making and credential requests were refused. SQL transaction tests verified minute/day limits and anonymous RPC denial, rolling all test counters back.

Playwright checked real output at 390/768/1280 without horizontal overflow. Earlier mocked checks covered success, insufficient evidence, 429 errors and scenario reset. Run `node scripts/evaluate-answers.mjs` for four real answers and, in a separate minute, `node scripts/evaluate-answers.mjs --refusals` for refusal checks. These consume the shared demo budget; run only with a confirmed free-tier project and inspect the prose as well as assertions.
